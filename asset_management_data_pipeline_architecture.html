Trusted Asset Management
Data Pipeline

A replay-safe, quality-controlled pipeline that turns daily asset-management files into trusted portfolio positions and traceable compliance exceptions.

Logical architecture · Technology-agnostic
Source & ingestion Bronze / raw Silver / validated Gold / curated Reject / quarantine path Solid arrows: data flow

Core business transformations

  • Build trusted positions from positions and/or transaction activity, using an explicitly documented position methodology.
  • Calculate market value from quantity × selected valid market price, with currency handling documented.
  • Join trades to restrictions using trade date within the restriction effective window and active status.

Required demonstration scenarios

  • Same transaction file delivered twice → no double count.
  • Missing price → explicit warning, quarantine or reject; publication impact visible.
  • Restricted-security trade → traceable compliance exception.
  • Mid-run interruption → restart / replay without partial or duplicate publication.
  • Increasing synthetic volumes → measure throughput and identify bottleneck.

Traceability contract

Carry run_id, batch_id, source_file, source_record_id, ingestion timestamp, validation result and reason code through the layers. Use stable business keys and rule/version metadata so each curated row can be explained.

Design assumptions to confirm in the implementation: the brief does not prescribe a technology stack, file format, position accounting method, base-currency conversion policy, or whether missing-price rows block an entire publication. Choose and document these decisions; the diagram shows logical responsibilities rather than asserting those unspecified policies.
